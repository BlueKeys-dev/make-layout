Problem

The apply routine mutates through multiple setElements calls, so a later missing replacement or cancelled confirmation can leave earlier effects applied and history split across writes. Reads from elementsRef.current between those scheduled writes can also be stale.

Solution

  • • locality: one mutation seam
  • • leverage: atomic undo/redo
  • • depth: confirmation stays an adapter
  • • tests cover state transitions
